ILG Forms callbacks

Open sync log

What these are

Three addresses that the ILG Forms platform calls when a form is submitted. Each one replaces an n8n workflow. Set them as the REST connector URL on the matching form in ILG Forms.

FormCallback URLReplaces n8n workflow
Incident form, with its list of propertiesAdd Incident
Appliance list formItems upload
Engineer single-appliance formEngineer Job Updater

How a call is made

  • Method POST, content type application/json. Send the form entry as ILG Forms normally does: ProviderId, IntegrationKey and Entry at the top level of the body.
  • Authentication is the ProviderId and IntegrationKey in the body. No login, token or fixed IP address is needed. The key is checked against the integration set up on this platform, and the call may only touch accounts linked to that integration.
  • Reply comes back within a second or two as JSON. Nothing is sent to ILG Forms during the call: any write back to a datasource is queued and sent moments later, with retries.
  • Sending the same entry twice is safe. An identical body is recognised and ignored. A changed resubmission updates what exists and never creates duplicates.

1. Incident form

Creates the incident if it is new, then creates or updates one item per property. For each new item, the item id is written back to the itemId column of the property's row in the main datasource.

initialVisitItem status. Only applied while the item is still at Faults, No Faults, Out or N/A, so an engineer's later status is never overwritten.

2. Appliance list form

Creates or updates one item per appliance in an existing incident, adds the engineer's comment, and builds full photo links. For each new item, systemID, systemAccountID and systemSectionID are written back to the appliance's row in the device datasource.

FieldNeededUsed for
page1.accountid, page1.incdidYesAccount id and incident id. The incident must already exist.
page1.customersName, houseNoName, address, postCode, telephoneNumber1, dateAndTimeNoCustomer details copied onto each appliance item.
page1.datasourceIDNoDevice datasource name. Defaults to the one set on the integration.
deviceReview.devices[]Nouniq_up / uniq row id, systemID (blank for a new appliance), make, model, serialNumber, applianceType, approxAgeYr, approxPurchasePrice, status (report status), repairStatus (item status), engineer, photo to photo4, comments.

3. Engineer single-appliance form

Updates one existing item and adds the engineer's comment. Reads Entry.AnswersJson.deviceReview.

FieldNeededUsed for
systemID, systemAccountIDYesThe item to update and its account.
make, model, serialNumber, applianceType, approxAgeYr, approxPurchasePrice, engineer, photoNoAppliance details. Blank values are ignored.
statusNoReport status.
deviceStatusNoItem status. Always applied when set: the engineer's form is the authority.
commentsNoSaved on the item and added as a comment once.

Replies

StatusMeaningWhat to do
200Processed. The body lists what happened to each property or appliance: create, update, link or skip, with a reason. "duplicate": true means an identical entry had already been processed.Nothing.
400A required field is missing, or the incident does not exist.Fix the form mapping. Retrying the same body will fail again.
401Unknown ProviderId or wrong IntegrationKey.Check the key on the form's connector.
403The account is not linked to this integration, or the integration is switched off.Link the account on this platform.
422The body is not valid JSON.Check the connector's content type and body.
5xxFault on this platform. Nothing was saved.Safe to retry.

Every call, accepted or rejected, appears in the sync log with the stored body for 30 days. That is the quickest way to see why a test call did what it did.

Testing a callback by hand

Save a body to entry.json and post it. Use a test incident id so it is easy to find and delete afterwards.

curl -X POST "/api/integrations/ilgforms/incident" \
  -H "Content-Type: application/json" --data @entry.json

The other direction

Changes made on this platform are pushed to ILG Forms automatically. There is nothing to configure in ILG Forms for these.

On this platformIn ILG Forms
Create an incidentNew row in the incident list datasource, with its post code and address
Rename an incident or change its post code or addressThat row is updated
Add an itemNew row in the main property datasource, so the property shows in the app. Skipped when that house already has a property row in the incident.
Add an item that has appliance details (make, model, serial number, type, age or price)Also a new row in the device datasource
Edit an itemIts row or rows are updated
Delete an itemIts row or rows are removed
Delete an incidentThe incident row and every property and appliance row under it are removed
